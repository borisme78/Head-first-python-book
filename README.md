## Chapter_11_3_4: Багатопотоковість у Flask застосунку

**Теми:**
- Асинхронне логування за допомогою потоків (`threading.Thread`)
- Неблокуючи логування запитів у базу даних
- Копіювання контексту запиту для роботи в окремому потоці (`copy_current_request_context`)
- Безпека: обробка помилок у потоках за допомогою `try/except`
- Побудова UI без чекання на завершення фонових операцій

**Файли:**
| Файл | Опис |
|------|------|
| `checker.py` | Декоратор для перевірки сесії `logged_in` та захисту маршрутів |
| `DBcm.py` | Контекстний менеджер `UseDatabase` для підключення до MySQL |
| `vsearch4web.py` | Flask-застосунок з **багатопотоковим логуванням** через `Thread` |
| `try_example.py` | Приклади використання функцій та обробки винятків |
| `static/hf.css` | Стилі для веб-інтерфейсу |
| `templates/base.html` | Базовий шаблон для сторінок |
| `templates/entry.html` | Форма для введення тексту |
| `templates/results.html` | Відображення результатів пошуку |
| `templates/viewlog.html` | Сторінка для перегляду логів з БД |

**Що було додано:**

1. **Модульна функція `log_request`** — записує запити у базу даних з захистом від помилок
   - Використовує плейсхолдери для безпеки від SQL-ін'єкцій
   - Обгорнута в `try/except`, щоб не перервати основну роботу

2. **Потокова обробка логування** у маршруті `/search4`
   - Запускає функцію `log_request` у **окремому потоці** через `Thread(target=log_request, args=(request, result))`
   - Це дозволяє користувачу **миттєво отримати результати пошуку**, не чекаючи на логування в БД
   - Логування продовжується на **фоні** без блокування відповіді сервера

3. **Демонстрація асинхронності** через `sleep(15)` у внутрішній функції `log_request`
   - Показує, як основна сторінка завантажується, поки логування ще працює

**Переваги багатопотоковості:**
- ✅ Користувач не чекає на запис у базу даних
- ✅ Сервер швидше реагує на запит
- ✅ Надалі можливо завантажити БД без впливу на UX
- ✅ Обробка помилок гарантує, що логування не ламає основний код
